OTP တိုင်းကို ချက်ချင်း သင့်ဖုန်းထံရောက်စေမယ့် Telegram Bot ဒီဇိုင်း

GSM hardware အခြေခံ → လက်ရှိ project အလုပ်လုပ်ပုံ → Telegram bot ဒီဇိုင်း → ဝင်ရောက်ခွင့် ထိန်းချုပ်မှု → မြင်ကွင်းပုံများ။ စာအရှည်ဖတ်ချင်မှ ဖတ်ပါ — ပုံတွေနဲ့ပဲ နားလည်သွားအောင် စီစဉ်ထားပါတယ်။

⚡အနှစ်ချုပ် — မေးခွန်း ၄ ခုကို တိုက်ရိုက်ဖြေပါမယ်

အောက်မှာရှိတဲ့ အားလုံးရဲ့ ချုံ့ထားတဲ့ မူကြမ်းပါ။ ဒီဇိုင်းအားလုံးကို သင်မေးထားတဲ့ မေးခွန်း ၄ ခုအတိုင်း စီထားပါတယ်။

❶ ကျွန်တော့်အဖွဲ့ အားလုံး OTP တွေကို ဘယ်လိုမြင်ကြမလဲ — (app ရှေ့မှာ ထိုင်နေရသူ တစ်ယောက်ပဲ မြင်ရတဲ့ အခြေအနေကနေ)?
ဒီ app က စက်တစ်လုံးတည်းအတွက် desktop program ပါ — စခရင်တစ်ခု၊ လုပ်ဖော်ကိုင်ဖက်တစ်ယောက်၊ network layer လုံးဝမရှိ (server မရှိ၊ database မရှိ)။ အမြန်ဆုံးနဲ့ သန့်ရှင်းဆုံး ဖြေရှင်းချက်က Telegram bot ပါ — OTP တစ်ခု ဆင်းမ်ဘဏ်ကိစ္စနဲ့ ရောက်လာတာနဲ့ စက္ကန့်ပိုင်းအတွင်း ခွင့်ပြုထားတဲ့ အဖွဲ့ဝင်တိုင်းရဲ့ ဖုန်းမှာ အသံနဲ့တကွ သတိပေးလာမယ်။ သတိထားမိမယ် — ကိုယ့် project roadmap (Memory/05-feature-roadmap.md) မှာတောင် "Telegram Bot & Webhook SMS Forwarding" ကို Feature #1၊ ဦးစားပေးအမြင့် အနေနဲ့ ရေးထားပြီးသားပါ။ ကိုယ့်စိတ်ကူးနဲ့ အစီအစဉ် ကိုက်နေတယ်။
❷ Telegram မှာ ဘယ်သူမဆို ဒီ bot ကို သုံးနိုင်မလား — ဒါမှမဟုတ် ကျွန်တော့်အဖွဲ့ပဲလား?
Allowlist (ခွင့်ပြုစာရင်း) နဲ့ ထိန်းပါတယ်။ အဖွဲ့ဝင်တိုင်းရဲ့ chat_id (အရေအတွက်ပါ — ဥပမာ 123456789) ကို Settings မှာ ထည့်သွင်းရမယ်။ Bot က စာပို့ပေးမှာက အဲဒီစာရင်းထဲက လူတွေကိုပဲ။ စာရင်းမှာမပါတဲ့သူက bot ကို ရှာတွေ့ပြီး စတင်ခွင့်တောင်းရင်တောင် — ဘာဖြေချင်စရာမရှိလို့ တိတ်ဆိတ်နေမယ်။ ခွင့်ပြုလိုက်တာနဲ့ တစ်ဖက်ချက်ကနေ ပိတ်လို့ရတဲ့ စနစ်ပါ။
❸ Local မှာ ဘယ်လိုချိတ်ဆက်မလဲ — ဘယ်လိုအလုပ်လုပ်မလဲ?
Hardware ဘက်မှာ ဘာမှမပြောင်းဘူး — SIM Bank → USB → PC ကို ဒီနေ့ကဲ့သို့ပဲ။ ပေါင်းထည့်မယ့်အရာက app ထဲက Forwarder module တစ်ခုပဲ — SMS အသစ် ရောက်လာတိုင်း api.telegram.org ကို HTTPS (port 443) နဲ့ ခေါ်ဆိုမှာ။ လိုအပ်ချက် — internet ရှိတဲ့ PC၊ app လည်ပတ်နေမှု၊ Live mode ဖွင့်ထားမှု (Auto-start Live Mode ဆိုတဲ့ setting ရှိပြီးသား)၊ အဖွဲ့ဝင်တိုင်းက bot ကို တစ်ခါတည်း ဖွင့်ပြီး Start နှိပ်ပြီးဖြစ်မှု။
❹ SMS OTP တွေကို တကယ်ဖတ်နိုင်မလား?
ဖတ်ပြီးသားပါ။ ဒီ app ထဲမှာ OTP ထုတ်ပေးတဲ့ အင်ဂျင် (extract_otp) အပြည့်အစုံ ပါပြီး — ဂဏန်း ၄–၈ လုံး၊ keyword စစ်တဲ့ cascade pattern၊ မြန်မာဂဏန်း (၀၁၂၃…) ပါ အားလုံး။ Bot ကတော့ app က decode ပြီးသား အချက်အလက်ကို ပို့ပေးရုံပဲ — အခက်ခဲဆုံးအပိုင်းတွေ ပြီးနေပြီ။ လိုနေတဲ့အရာက "ထွက်ပေါက်" တစ်ခုတည်းပဲ။

၁အရင်ဆုံး — GSM hardware ကို ရိုးရိုးသားသားနဲ့ နားလည်ကြရအောင်

Bot ဒီဇိုင်းမဆွဲခင် အောက်ခံ စက်ကိရိယာကို တကယ်နားလည်ဖို့ လိုပါတယ်။ ထင်ထားတာထက် ရိုးသွားပါတယ်။

📡 GSM modem ဆိုတာ ဘာလဲ?

GSM modem ဆိုတာ ဖုန်းတစ်လုံးရဲ့ အလုပ်လုပ်တဲ့ အသဲကို စခရင်နဲ့ ကီးဘုတ်မပါဘဲ ယူထားတာ — ဆင်းမ်စလော့တစ်ခု၊ ရေဒီယိုတစ်ခု၊ serial interface တစ်ခု။ အဲဒါကို လက်နဲ့ မနှိပ်ဘဲ ကွန်ပျူတာကနေ AT command ဆိုတဲ့ စာသားညွှန်ကြားချက်တွေနဲ့ ပြောကြားရတဲ့ စနစ်ပါ။

SIM Bank (GSM modem pool) ကတော့ modem ၈ / ၁၆ / ၃၂ / ၆၄ လုံးကို ဘောဒီတစ်ခုတည်းထဲ ထည့်ပြီး အထဲမှာ USB hub နဲ့ တစ်ပေါင်းတစ်စည်းတည်း ထုတ်ပေးထားတာပါ။ PC တစ်လုံးနဲ့ ချိတ်လိုက်ရင် operating system ကြားမှာ serial port အရေအတွက်အတိုင်း တွေ့ရမှာ — Linux မှာ /dev/ttyUSB0…31၊ Windows မှာ COM3…COM34။ port တစ်ခု = SIM တစ်ပတ်။

⌨️ AT command — modem တွေ ပြောတဲ့ ဘာသာစကား

၉၀ ခုနှစ်ကတည်းက စံချိန်စံညွှန်းဖြစ်နေတဲ့ စာသားညွှန်ကြားချက်တွေ။ ဒီ app ကလည်း အတိအကျ ဒီ command တွေပဲ သုံးပါတယ် —

Commandအဓိပ္ပာယ်ပုံမှန်တုံ့ပြန်ချက်
AT"အသက်ရှိသေးလား" — အသက်ရှိမှု စစ်တာOK
AT+CCIDSIM ရဲ့ ICCID (ကတ်အိုင်ဒီ) ဖတ်တာ8968...ဂဏန်း ၁၅ လုံး

+CMTI: "SM",5အချက်ပေးလာတာ — "SMS အသစ် ရောက်လာပြီ၊ အကွက် ၅ မှာ သိမ်းထားတယ်"(Live mode စောင့်ကြည့်နေတဲ့အရာ)

📩 OTP SMS တစ်ခုက တကယ်ဘယ်လို ခရီးလမ်းလာတာလဲ?

မြန်မာနိုင်ငံမှာဆိုရင် ဆက်သွယ်ရေးလုပ်ငန်းများ (MPT / ATOM / Ooredoo / Mytel) က မက်ဆေ့ချ်ကို စတင်ပို့ပါတယ်။ တစ်ခုလုံးရဲ့ ခရီးလမ်း —

📦 SIM storage က သေးငယ်တယ်

SIM card တစ်ပတ်မှာ message ၂၀–၅၀ စောင်ပဲ သိမ်းလို့ရတယ်။ ပြည့်သွားရင် modem က SMS အသစ်တွေကို တိတ်တဆိတ် ငြင်းပယ်လိုက်တယ်။ ဒါကြောင့် ဒီ app မှာ ၁၀ မိနစ်လျှင် တစ်ကြိမ် SIM သုတ်သင်မှု ထည့်ပြီးသားပါ — အကွက်တွေ လွတ်နေအောင်။

🧩 PDU mode နဲ့ မြန်မာစာ

SMS က hex data (PDU) အနေနဲ့ ရောက်လာတယ်။ ဒီ app က GSM-7 (အင်္ဂလိပ်)၊ UCS-2 (Unicode — မြန်မာစာ အပါအဝင်) တွေကို decode လုပ်ပြီး အပိုင်းခွဲပို့လိုက်တဲ့ ရှည်စာတွေကို တစ်ခုတည်း ပြန်ပေါင်းပေးတယ်။

၂လက်ရှိ project က ဘယ်လိုအလုပ်လုပ်တယ် — ဘယ်နေရာမှာ ရပ်တန့်နေတယ်

စာကြောင်းတစ်ကြောင်းနဲ့ ချုပ်ရရင် — ပြောလို့ကောင်းတဲ့ အင်ဂျင်တစ်လုံး၊ ဓာတ်ပိုင်းပိုက်လိုင်းမရှိဘူး။ အားလုံးက လူတစ်ယောက်ရဲ့ မျက်လုံးနှစ်လုံးထိပ်မှာ ပြီးဆုံးတယ်။

ဒီနေ့ မရှိသေးတဲ့အရာများ

  • Network layer လုံးဝမရှိ — app က internet ကို မသုံးဘူး (update စစ်တာပဲ 除外)
  • message တွေ RAM ထဲမှာပဲ — app ပိတ်လိုက်ရင် မှတ်တမ်း အပြတ်
  • မြင်နိုင်တဲ့သူ = စခရင်ရှေ့မှာ ပစ်ရှိနေသူပဲ

ပြည့်စုံပြီးသား အပိုင်းများ

  • Live mode — +CMTI ကို စောင့်ပြီး SMS အသစ်ကို ချက်ချင်းဖမ်းတဲ့စနစ် ✅
  • OTP extractor — extract_otp၊ မြန်မာဂဏန်းပါ ✅
  • sms:new event — "စာအသစ်ရောက်ပြီ" ဆိုတဲ့ အချက်ပေးချက်က အတိအကျ မှန်တဲ့နေရာမှာ ပြီးသားပဲ ✅ — forwarder အတွက် အကောင်းဆုံး ချိတ်ဆက်မှတ်
💡 အဓိကအချက် — OTP bot တစ်လုံးရဲ့ အခက်ခဲဆုံး အပိုင်းတွေ (SMS ဖတ်၊ decode၊ code ထုတ်) က ဒီ project ထဲမှာ ပြီးနေပြီ။ လိုနေတဲ့အရာက နောက်ဆုံးတစ်ဆင့် — အပြင်ကမ္ဘာကို တံခါးတစ်ခုပဲ။

၃Bot ဒီဇိုင်း — push-only၊ မိနစ်ပိုင်းအတွင်း

Bot ကို အလွန်ရိုးရိုးသားသား ဒီဇိုင်းထားပါတယ် — မိနစ်အနည်းငယ်အတွင်း တည်ဆောက်ပြီးသား၊ အလုပ်လုပ်ပုံလည်း ရိုးတယ်။

🤖 Telegram bot — စက္ကန့် ၃၀ နားလည်စေတဲ့ မော်ဒယ်

  • Bot ဆိုတာ @BotFather ဆိုတဲ့ တရားဝင် bot ဆီကနေ ဖန်တီးတဲ့ အထူး account တစ်ခု။ ဖန်တီးပြီးရင် token တစ်ခု ရပါမယ် (123456:ABC-... ပုံစံ) — အဲဒါက bot ရဲ့ အမည်နဲ့ စကားဝှက် နှစ်ခုတစ်ပြိုင်ပါ။
  • Bot က Telegram server ပေါ်မှာ မလည်ပတ်ဘူး — ကိုယ့် app က internet ကနေ Telegram API ကို ခေါ်တာ (token နဲ့အတူ)။ ဒါကြောင့် port forwarding မလို၊ public IP မလို၊ server ငှားစရာမလိုဘူး။
  • Bot တွေက ပြောစမှာ စပြောလို့မရ — Telegram က ပိတ်ထားတယ်။ user တစ်ယောက်က bot ကို ဖွင့်ပြီး Start နှိပ်ပြီးမှ စာပို့ခွင့်ရတယ်။ ဒါက Telegram ရဲ့ စပန်းရင်ကတည်းက ပေါ်လစီပါ။
⚠️ ဒီဇိုင်းက push-only: bot က ဘာမှမနာဘူး၊ ဘာမှ မဖြေဘူး၊ command လည်း မရှိဘူး။ ဘယ်သူ့ဆီကမှ လက်ခံတာမရှိ — OTP တွေကို ပို့ထုတ်ရုံပဲ။ တိုက်ခိုက်ခံရနိုင်တဲ့အပိုင်း အနည်းဆုံး။

  • user တစ်ယောက်ချင်းဆို dialog တစ်ခုလျှင် — စက္ကန့်တစ်ချက်ကို စာတစ်စောင် (တစ်မိနစ်ကို ~၂၀)
  • bot တစ်လုံးချင်း global — စက္ကန့်ကို စာ ~၃၀
  • ကျော်သွားရင် Telegram က 429 Too Many Requests ပြန်ပြီး retry_after ဆိုတဲ့ စောင့်ရမယ့်စက္ကန့်ပါပို့တယ် — အဲဒါကို လေးစားပြီး နောက်ထပ်ပို့ရတယ်

ဒီဇိုင်းရဲ့ ဖြေရှင်းချက်

  • ချိတ်းထားတဲ့ queue — တစ်ကြိမ်လျှင် ~၃ စက္ကန့်၊ worst case မိနစ်တစ်မိနစ်ကို ၂၀ ရှိမယ် — limit အောက်မှာပဲ
  • burst ဖြစ်သွားရင်တောင် 429 retry_after ကို လေးစားပြီး ပြန်ပို့မယ်
  • OTP တွေက မိနစ်ပိုင်းအတွင်း သက်တမ်းကုန်တတ်တာမို့ ၃ စက္ကန့် ချိတ်းတာကို သူတစ်ပါး မသိနိုင်ဘူး

၄ဝင်ရောက်ခွင့် ထိန်းချုပ်မှု — allowlist စနစ်

နိုင်ငံခြားက ဘယ်သူမှ မဝင်နိုင်အောင် — ခွင့်ပြုထားတဲ့ chat_id တွေပဲ စာလက်ခံရမယ်။

စတင်အသုံးပြုပုံ — အဆင့် ၅ ဆင့်၊ တစ်ခါတည်း

✅ ဒီမော်ဒယ်ရဲ့ အားသာချက်များ

  • သူ့သူ့ဖုန်း သူ့သူ့ဆီ ကိုယ်စီရတယ် — တစ်ယောက်ကို တစ်ယောက် စာမမြင်ရ
  • ခွဲခြားနိုင်တယ် — ဘယ်သူ့ကို ပိတ်မလဲဆိုတာ allowlist နဲ့ ထိန်းလို့ရ
  • ရိုးရိုးရှင်းရှင်း — နားလည်ရလွယ်တဲ့ လုံခြုံရေးမော်ဒယ်

လက်ခံရမယ့် အားနည်းချက်များ

  • အဖွဲ့ဝင်တိုင်းရဲ့ chat_id ကို တစ်ခုချင်း စုဆောင်းရတယ်
  • အဖွဲ့ဝင်အသစ်ဝင်လာတိုင်း admin က လက်ဖြင့် ထည့်ပေးရတယ်
  • OTP တစ်ခုကို လူ ၃ယောက်ရှိရင် စာ ၃ စောင် ပို့ရတယ် (rate limit ပိုစားတယ်)
💡 နောက်ဆက်တွဲ မှတ်ချက် — allowlist စနစ်က လူအနည်းငယ်အတွက် ကောင်းပေမယ့် အဖွဲ့အတွင်း မျှဝေချင်တဲ့အခါ "Group chat တစ်ခုထဲ ပို့တဲ့" ဒီဇိုင်းကလည်း ရှိပါတယ် (တစ်နေရာတည်းကိုပဲ ပို့ရုံ — group chat_id တစ်ခုတည်း)။ နှစ်ခုလုံးကို ဒီ app ရဲ့ Settings နဲ့ အလွယ်ပဲ ပြောင်းလို့ရအောင် ဒီဇိုင်းထုတ်ထားနိုင်ပါတယ်။

၅Network နဲ့ "local" — ဘာက ဘယ်နေရာမှာ လည်ပတ်တယ်

မကြာခဏ ရှုပ်ထွေးစေတဲ့ အချက် — SIM bank က အိမ်ရှေ့ hardware ပေမယ့် Telegram က ကမ္ဘာအနှံ့ ဝန်ဆောင်မှု။ ဒီကြားထဲမှာ တံတားသဖွယ် ချိတ်ပေးတာက app ပါ။

အရာဘယ်နေရာမှာရှိလဲInternet ကို ဘာရောက်လဲ?
SIM bank + SIM များ 🏠 သင့် PC နားမှာပဲထွက်သွားတဲ့ ချိတ်ဆက်မှု တစ်ခုတည်း:
api.telegram.org:443 (HTTPS)
အဝင်လက်ခံတာ ဘာမှမရှိ။ နားထောင်တာ ဘာမှမရှိ။
App (Rust + Svelte) 🖥️ အဲဒီ PC ထဲမှာပဲ
OTP message များ 🧠 RAM (၂ နာရီအတွင်း)
Telegram server များ ☁️ Telegram (ကမ္ဘာအနှံ့)— သူတို့က စာလက်ခံပြီး ကိုယ့် allowlist က user တွေဆီ ဖြန့်ပေးတယ်

🏠 LAN အတွင်းချည်း (မရွေးချယ်ထားတဲ့ နည်းလမ်း)

အိမ်ထဲက Wi-Fi ချိတ်ပြီး ဖုန်းတွေက စစ်ဆေးခိုင်းတဲ့ သေးငယ်တဲ့ local web server တစ်ခု လည်ပတ်နိုင်ပါတယ်။ မရွေးချယ်တဲ့အကြောင်းတွေက —

  • Push မရှိ — ဖုန်းတွေက ထပ်ခါထပ်ခါ စစ်နေရမယ် (ဒါမှမဟုတ် စာမျက်နှာ ဖွင့်ထားရမယ်)
  • ဖုန်းက Wi-Fi ကနေ ထွက်လိုက်တာနဲ့ ပျက်သွားတယ်
  • Port / IP စီမံခန့်ခွဲမှုကိုယ်တိုင်က ရှုပ်ထွေးတဲ့ အလုပ်တစ်ခု

☁️ Telegram နည်း (ရွေးချယ်ထားတဲ့နည်း)

PC က ထွက်သွားတဲ့ HTTPS ခေါ်ဆိုမှုတစ်ခုလုံးလုံး လုပ်ရုံပဲ — ကျန်တာကို Telegram ရဲ့ infrastructure က လုပ်ပေးတယ်:

  • တကယ့် push — ကမ္ဘာပေါ်မှာ ဘယ် network ကမဆို အလုပ်လုပ်တယ်
  • Port forwarding မလို၊ static IP မလို၊ DNS မလို
  • ပို့ရောက်မှု + အသံတွေ့အချက်ပြမှုက Telegram ရဲ့ တာဝန် — ကိုယ့်တာဝန် မဟုတ်တော့ဘူး
🇲🇲 မြန်မာ့အချက်အလက် တကယ့်အခြေအနေ — internet ပိတ်ချိန်တွေမှာ api.telegram.org ကို ISP အချို့က အပြည့်အဝ ပိတ်ချထားခဲ့ဖူးပါတယ်။ Forwarder က ချိတ်လို့မရရင် ရှင်းရှင်းလင်းလင်း error မှတ်ပါမယ်။ ကြိုတင်ဖြေရှင်းနည်းက SOCKS5 proxy setting (Settings မှာ ကွက်တစ်ကွက်) — Bot API က socks5h:// proxy တွေနဲ့ အလုပ်လုပ်တယ်။ MTProto proxy link တွေကတော့ Telegram client app တွေအတွက်ပဲ ကူညီတယ် — bot API ခေါ်ဆိုမှုတွေအတွက် မဟုတ်ဘူး။

၆မြင်ကွင်းပုံများ — ဘယ်လိုမြင်ရမလဲ

Code မဟုတ်ဘူး — ရည်မှန်းထားတဲ့ ပုံစံခွက်တွေပါ။ အရင်က app ထဲမှာ ထည့်မယ့် tab၊ နောက် bot စကားပြောခန်း။

၇လမ်းညွှန် အကြံပြုချက် — တည်ဆောက်စဉ်အဆင့်

အောက်ပါအစီအစဉ်ကို ဒီလိုစီထားတာက — အဆင့်တိုင်းက ကိုယ်တိုင်တစ်ခုတည်း အသုံးဝင်အောင်၊ နောက်မှာ ဘာမှ ပြန်မပစ်ရအောင်ပါ။

အဆင့်ဘာလဲအလုပ်ပမာဏဒီစဉ်အတိုင်းဖြစ်ရတဲ့အကြောင်း
၀ Telegram forwarder — MVP (ဒီစာတမ်း) သေး အနည်းဆုံး code နဲ့ အများဆုံး အားသာချက် — sms:new event နေရာမှာ HTTP ခေါ်ဆိုမှုတစ်ခုပဲ ထည့်ရတယ်။ အခြားအရာ ဘာမှမပြောင်းဘူး။
၁ ခိုင်ခန့်အောင်လုပ်ခြင်း — 429 ကိုင်တွယ်မှု၊ internet ပြတ်လျှင် ပြန်ပို့တဲ့ queue၊ log ထဲ token ဖျောက်ခြင်း သေး MVP ကို တကယ့် network အခြေအနေနဲ့ ရှင်သန်အောင် လုပ်ပေးတယ် (ပြီးတော့ AGENTS.md ရဲ့ log ထဲ လျှို့မှတ်မထားရ စည်းမျဉ်းနဲ့လည်း ကိုက်တယ်)။
၂ message မှတ်တမ်း အမြဲတမ်းသိမ်း (SQLite) + ရှာဖွေမှု အလယ်အလတ် RAM ထဲပဲ ရှိတဲ့ မှတ်တမ်းက app ရဲ့ အကြီးဆုံး အားနည်းချက် — Telegram မှတ်တမ်းနဲ့လည်း တွဲသွားတယ်။
၃ ပို့ရမယ့်နေရာ များရန် — group အများ၊ SIM အလိုက် စည်းမျဉ်း ("KBZPay SIM → ငွေစာရင်းအဖွဲ့") အလယ်အလတ် တစ်နေရာ အလုပ်လုပ်ပြီးရင် N နေရာက ဇယားတစ်ခုပဲ ဖြစ်သွားတယ် — ဒါပေမယ့် ပထမ အခြေခံ အလုပ်လုပ်ပြီးမှ။
၄ HTTP API / web dashboard — ကိုယ့်စနစ်တွေထဲ တိုက်ရိုက်ချိတ်ဖို့ ကြီး အလေးဆုံးရွေးချယ်စရာ — အခြား software တွေက OTP တွေကို ပရိုဂရမ်နဲ့ ယူသုံးမှသာ တန်ဖိုးရှိတယ်။
💡 ရိုးရိုးသားသား အကြံပြုချက် — အဆင့် ၀ ကို ဒီစာတမ်းမှာ ဖော်ပြထားတဲ့အတိုင်း တည်ဆောက်ပြီး ၂ ပတ်လောက် တကယ့်အသုံးနဲ့ စမ်းကြည့်ပါ။ ရှေ့ဆောင်ပုံစံ၊ ပူဖောင်းပုံစံ၊ ဖျောက်တာ — အားလုံးကို အသုံးပြုပြီးမှ ပြင်ရတာ စရိတ်သက်သာတယ်။ အဆင့် ၀ က တကယ့်အလုပ်လုပ်မှု မမြင်ခင် အဆင့် ၃ ကို ဒီဇိုင်းမဆွဲနဲ့။

၈မေးလေ့ရှိတဲ့ မေးခွန်းများ

အဖွဲ့ဝင်တိုင်း bot ကို ဖွင့်ပြီး Start နှိပ်ရမလား?
ဟုတ်တယ်၊ တစ်ခါတည်းပဲ။ Telegram စည်းမျဉ်းအရ bot တွေက ပြောစမှာ ပထမဆုံးစကားပြောလို့မရဘူး — user က bot ကို ဖွင့်ပြီး Start နှိပ်မှ အဲဒီ user ဆီ စာပို့ခွင့် ပွင့်တယ်။ တစ်ခါနှိပ်ပြီးရင်တော့ နောက်တစ်ခါ မလိုတော့ဘူး။
ဘယ်သူမဆို bot ကို ရှာတွေ့ပြီး စတင်ခွင့်တောင်းရင် ဘာဖြစ်မလား?
ဘာမှမဖြစ်ဘူး။ bot ရဲ့ ပို့ရမယ့်စာရင်းက allowlist ထဲကပဲ။ Start နှိပ်လို့ ရှိလာတဲ့ chat_id က allowlist ထဲ မပါရင် — တိတ်ဆိတ်နေမယ်။ ဘယ်သူ့ဆီကမှ ဘာမှ မထုတ်ပေးဘူး။
တစ်ယောက်ယောက်က bot အတုဆောက်ပြီး အတု OTP ထည့်နိုင်မလား?
Telegram ရဲ့ ပုံမှန်နည်းလမ်းနဲ့ဆို မရဘူး — bot အနေနဲ့ စာပို့ဖို့အတွက် token လိုတယ်၊ အဲဒါက ကိုယ့် PC ထဲမှာပဲရှိတယ်။ PC ကို ကာကွယ်တာ = token ကို ကာကွယ်တာ။ Token ယိုစိမ့်ခဲ့ရင် @BotFather ရဲ့ /revoke နဲ့ ချက်ချင်း သတ်ပြီး အသစ်တွေ့လို့ရတယ်။
PC မှာ internet မရှိရင် ဘာဖြစ်မလား?
OTP ပို့တာ ခဏရပ်မယ်။ SMS တွေကတော့ SIM တွေထဲနဲ့ app ထဲ ဆက်စုနေမယ်။ အဆင့် ၁ ရဲ့ ပြန်ပို့ queue နဲ့ internet ပြန်လာရင် ကျန်တာတွေ ဆက်ပို့မယ်။ အဲဒီအကြာမှာ SIM အကွက်တွေ မပြည့်အောင်ကတော့ ၁၀ မိနစ်ကြာတစ်ကြိမ် သုတ်သင်မှုက ထိန်းပေးထားတယ်။
မြန်မာစာ OTP တွေနဲ့လည်း အလုပ်လုပ်မလား?
ဟုတ်တယ် — decoder က UCS-2 မြန်မာစာကို ကိုင်တွယ်ပြီးသားပြီး extract_otp က မြန်မာဂဏန်း (၀၁၂၃…) တွေကိုပါ အသိအမှတ်ပြုတယ်။ ပို့တဲ့ပူဖောင်းထဲမှာ မူရင်းစာသား အတိုင်းပါလာမယ်။
ဘယ်လောက်မြန်မြန် ရောက်မလား?
SMS ရောက်ကနေ ဖုန်းမြည်တဲ့အထိ ~၃–၈ စက္ကန့်ပါ။ app က စက္ကန့်တစ်ချက်အောက်မှာ decode ပြီးသား၊ forwarder က ချက်ချင်းပုံစံချ၊ queue ကလည်း burst မဟုတ်ရင် ဘာမှ မထပ်ထည့်ဘူး။ ပုံမှန်အခြေအနေဆို — ဝင်းဒိုးပြောင်းဖို့ မကုန်ခင်မှာပဲ ဖုန်းသံကြားရတယ်။
OTP တွေအတွက် Telegram က ဘေးကင်းလား?
ကောင်းတဲ့အဆင့်အထိ — လမ်းမှာ TLS ပါတယ်၊ ဒါပေမယ့် ကြားခံ chat တွေမှာ end-to-end တိုက်ရိုက်ရှိမထားဘူး၊ မှတ်တမ်းတွေ Telegram server ပေါ်မှာ သိမ်းတယ်။ ဒီဇိုင်းထဲ ထည့်ထားတဲ့ အကာအကွယ်တွေက — token ကို local မှာပဲသိမ်းတာ၊ log ထဲ ဖျောက်တာ၊ ပို့လို့မရဘူးဖြစ်သွားရင် ချက်ချင်း ပိတ်ချင်ရတဲ့ စနစ်။ အများစုအဖွဲ့တွေအတွက် အဆင်ပြေမှုက ကျန်တဲ့အန္တရာယ်ထက် ပိုကြီးတယ် — ဒါပေမယ့် သိနားလည်ပြီး ဆုံးဖြတ်သင့်တဲ့အရာပါ။
ဘာကြောင့် Telegram လဲ — တခြားနည်းတွေ မရှိဘူးလား?
ရှိတယ် — email၊ ကိုယ်ပိုင် server၊ LAN web app။ Telegram ကို ရွေးတဲ့အကြောင်းက — အဲဒါထက် တည်ဆောက်ရလွယ်တာ၊ တကယ့် push ပါတာ၊ ကမ္ဘာအနှံ့ အလုပ်လုပ်တာ၊ setup အားလုံး မလိုတာ၊ အဖွဲ့ဝင်တိုင်း အလေ့အကျင့်အရ စာလုံးတွေ့တာနဲ့ အသံတွေ့တာပါ။
